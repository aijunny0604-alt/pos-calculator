프로그램 소개

이 프로그램은 무엇인가요?

영준이의 POS 재고관리 시스템은 자동차 배기 부품(머플러, 파이프, 레조네이터 등)을 판매하는 매장에서 사용하는 맞춤형 POS(Point of Sale) 시스템입니다. 쉽게 말해, 가게에서 물건을 팔 때 쓰는 계산대 프로그램을 웹으로 만든 것입니다.

일반적인 POS기는 비싸고 정해진 기능만 쓸 수 있지만, 이 프로그램은 웹 브라우저만 있으면 PC, 태블릿, 스마트폰 어디서든 사용할 수 있습니다.

React 18 - UI 라이브러리

비유: 레고 블록과 같습니다. 버튼, 입력창, 카드 같은 작은 블록(컴포넌트)을 만들고, 이것들을 조합해서 전체 페이지를 만듭니다.

  • 컴포넌트 기반 - 화면의 각 부분을 독립적인 블록으로 관리
  • 가상 DOM - 변경된 부분만 실제 화면에 업데이트하여 빠른 성능
  • 선언적 UI - "이런 데이터가 있으면 이렇게 보여줘"라고 선언하면 됨

Vite - 빌드 도구

비유: 요리사의 전자레인지와 같습니다. 코드를 넣으면 브라우저가 이해할 수 있는 형태로 빠르게 변환해줍니다.

  • 초고속 개발 서버 - 코드를 저장하면 0.1초 만에 브라우저에 반영
  • HMR (Hot Module Replacement) - 페이지 새로고침 없이 변경사항 즉시 반영
  • 최적화 빌드 - 배포 시 코드를 압축하고 최적화

Tailwind CSS v3 - 유틸리티 CSS 프레임워크

비유: 옷장에 미리 분류된 옷 조각들과 같습니다. "파란 상의(bg-blue-500)", "둥근 모서리(rounded-lg)", "그림자(shadow-md)" 같은 조각을 조합해서 디자인을 완성합니다.

Supabase - 백엔드 서비스

비유: 클라우드 금고와 같습니다. 데이터(제품, 주문, 고객 정보)를 안전하게 저장하고, 필요할 때 꺼내 쓸 수 있습니다. 직접 서버를 만들 필요 없이 API만 호출하면 됩니다.

  • PostgreSQL 데이터베이스 - 관계형 DB를 자동으로 제공
  • REST API - HTTP 요청으로 데이터 CRUD 가능
  • 실시간 구독 - 데이터 변경 시 자동 알림
  • 인증 - API Key 기반 접근 제어

Gemini 2.5 Flash - AI 모델

비유: 매우 똑똑한 비서와 같습니다. 카카오톡으로 "플랜지 63 5개, 카본 93 듀얼 3개" 같은 메시지를 보내면, AI가 자동으로 제품명과 수량을 정확히 인식해서 주문서를 만들어줍니다.

1. main.jsx - 앱의 시작점

// HTML에서 id="root"인 요소를 찾아서 App 컴포넌트를 렌더링

2. vite.config.js - 빌드 설정

Vite에게 "이 프로젝트는 React를 사용하고, GitHub Pages의 /pos-calculator/ 경로에 배포할 거야"라고 알려주는 설정 파일입니다.

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],       // React JSX 변환 플러그인
  base: '/pos-calculator/',  // GitHub Pages 배포 경로
})
주의: base 설정
base는 반드시 vite.config.js 파일 안에서 설정해야 합니다. 빌드 명령어에 --base 플래그를 넣으면 Git Bash가 경로를 /Program Files/Git/pos-calculator/로 잘못 변환해서 빈 페이지가 됩니다.

React 기초 개념

React를 이해하기 위해 꼭 알아야 할 핵심 개념들을 실제 프로젝트 코드와 함께 설명합니다.

컴포넌트 (Component) = 레고 블록

비유: 레고로 집을 만들 때 문, 창문, 벽, 지붕을 각각 만들고 조립합니다. React에서도 화면의 각 부분을 컴포넌트라는 블록으로 만듭니다.

// 각 페이지가 하나의 컴포넌트입니다
function OrderDetailModal({ ... }) { ... }   // 주문 상세 모달
function SavedCartsPage({ ... }) { ... }     // 저장된 장바구니
function CustomerListPage({ ... }) { ... }   // 거래처 관리
function TextAnalyzePage({ ... }) { ... }    // AI 주문 인식
function AdminPage({ ... }) { ... }          // 관리자 페이지
function WelcomeSplash({ ... }) { ... }      // 스플래시 화면
function PriceCalculator() { ... }           // 메인 앱 (최상위)

Props = 택배 상자

비유: 부모가 자녀에게 택배를 보내는 것과 같습니다. 부모 컴포넌트가 자식 컴포넌트에게 데이터를 전달합니다.

// PriceCalculator(부모)가 OrderPage(자식)에게 데이터를 전달
<OrderPage
  cart={cart}                    // 장바구니 데이터
  priceType={priceType}          // 가격 유형
  totalAmount={totalAmount}      // 총액
  formatPrice={formatPrice}      // 가격 포맷 함수
  onSaveOrder={handleSaveOrder}  // 저장 함수
/>

// OrderPage에서 Props를 받아서 사용
function OrderPage({ cart, priceType, totalAmount, formatPrice, onSaveOrder }) {
  return (
    <div>
      {cart.map(item => (
        <div key={item.id}>
          {item.name} - {formatPrice(item.price)}
        </div>
      ))}
    </div>
  );
}

State (useState) = 칠판

비유: 칠판에 적힌 정보와 같습니다. 칠판의 내용이 바뀌면 학생들(화면)이 새 내용을 봅니다. State가 변경되면 React가 자동으로 화면을 다시 그립니다.

// 실제 프로젝트의 PriceCalculator에서 사용하는 state들
const [searchTerm, setSearchTerm] = useState('');          // 검색어
const [selectedCategory, setSelectedCategory] = useState('전체');
const [cart, setCart] = useState([]);                     // 장바구니
const [priceType, setPriceType] = useState('wholesale');    // 도매/소매
const [isLoading, setIsLoading] = useState(false);        // 로딩 상태
const [isOnline, setIsOnline] = useState(true);           // 온라인 상태

// 검색어가 바뀔 때
<input
  value={searchTerm}
  onChange={(e) => setSearchTerm(e.target.value)}  // 칠판에 새 내용 적기
/>
useState 규칙
useState는 항상 [값, 변경함수] 쌍을 반환합니다. 값을 직접 수정하면 안 되고, 반드시 변경 함수를 통해 바꿔야 합니다. cart = [] (잘못됨) vs setCart([]) (올바름)

useEffect = 알람 시계

비유: "특정 조건이 되면 이 일을 해줘"라고 설정하는 알람과 같습니다. 컴포넌트가 화면에 나타나거나, 특정 값이 변할 때 자동으로 실행됩니다.

// 1. 앱 시작 시 데이터 불러오기 (빈 배열 = 처음 한 번만)
useEffect(() => {
  loadProducts();
  loadCustomers();
}, []);

// 2. 카테고리 목록이 변할 때 자동 반응
useEffect(() => {
  if (dynamicCategories.length > 0) {
    const initial = {};
    dynamicCategories.forEach(cat => initial[cat] = true);
    setExpandedCategories(initial);
  }
}, [dynamicCategories]);  // dynamicCategories가 변할 때마다 실행

// 3. 정리(cleanup) 함수가 있는 useEffect
useEffect(() => {
  const handleEsc = (e) => {
    if (e.key === 'Escape') onClose();
  };
  window.addEventListener('keydown', handleEsc);
  return () => window.removeEventListener('keydown', handleEsc);  // 정리!
}, [isOpen]);

useMemo = 메모장

비유: 계산 결과를 메모장에 적어두는 것입니다. 같은 계산을 반복하지 않고, 입력이 바뀔 때만 다시 계산합니다.

const dynamicCategories = useMemo(() => {
  const sourceProducts = products.length > 0 ? products : priceData;
  return [...new Set(sourceProducts.map(item => item.category))];
}, [products]);

useCallback = 함수 보관함

비유: 자주 쓰는 레시피를 서랍에 보관하는 것입니다. 매번 새 레시피를 쓰는 대신 보관된 것을 꺼내 씁니다.

const handleAddToCart = useCallback((product) => {
  setCart(prev => {
    const existing = prev.find(item => item.id === product.id);
    if (existing) {
      return prev.map(item =>
        item.id === product.id
          ? { ...item, quantity: item.quantity + 1 }
          : item
      );
    }
    return [...prev, { ...product, quantity: 1 }];
  });
}, []);

useRef = 이름표

비유: 특정 물건에 이름표를 붙여두는 것입니다. 화면이 다시 그려져도 이름표는 그대로 남아있습니다.

const toastTimerRef = useRef(null);
const savingToCartRef = useRef(new Set());

// 이전 타이머를 취소하고 새 타이머 설정
if (toastTimerRef.current) clearTimeout(toastTimerRef.current);
toastTimerRef.current = setTimeout(() => setToast(null), 3000);

페이지별 기능 설명

1. 메인 대시보드 (카탈로그)

앱을 열면 가장 먼저 보이는 화면입니다. 모든 제품을 카테고리별로 보여주고, 검색과 장바구니 기능을 제공합니다.

  • 카테고리별 제품 목록 (접기/펼치기 가능)
  • 실시간 검색 (순차 매칭 + 단어별 매칭 지원)
  • 도매가/소매가 전환 토글
  • 장바구니에 제품 추가/수량 조절/삭제
  • 수량별 자동 할인 계산

2. 주문서 작성 (OrderPage)

장바구니에 담은 제품들을 확인하고 주문을 확정하는 페이지입니다.

  • 자동 주문번호 생성 (ORD-20260316-0001 형식)
  • 거래처 자동완성 (이름 입력 시 기존 거래처 검색)
  • 주문서 복사 (클립보드에 텍스트로 복사)
  • 제품 추가/교체/수량 변경 가능

3. 주문 내역 (OrderHistoryPage)

과거에 저장한 모든 주문을 조회합니다. 날짜별 필터링, 검색, 삭제가 가능합니다.

4. 저장된 장바구니 (SavedCartsPage)

주문 전에 장바구니를 임시 저장하는 기능입니다. 나중에 불러와서 주문을 완료할 수 있습니다.

5. 택배 송장 (ShippingLabelPage)

택배 발송에 필요한 송장 라벨을 자동 생성합니다. 보내는 사람과 받는 사람 정보를 입력하면 인쇄 가능한 라벨이 만들어집니다.

6. 거래처 관리 (CustomerListPage)

  • 거래처별 주문 이력 조회
  • 반품 처리 및 기록
  • 블랙리스트 관리

7. 재고 현황 (StockOverviewPage)

전체 제품의 재고 상태를 한눈에 파악합니다. 부족 재고 알림 기능이 있습니다.

8. AI 주문 인식 (TextAnalyzePage)

카카오톡 메시지나 메모를 붙여넣으면 AI가 자동으로 제품명과 수량을 인식합니다. 자세한 설명은 10장에서 다룹니다.

Supabase 데이터베이스 연동

Supabase는 이 프로젝트의 백엔드(서버) 역할을 합니다. 모든 데이터가 Supabase의 PostgreSQL 데이터베이스에 저장됩니다.

연결 설정

const SUPABASE_URL = 'https://xxxx.supabase.co';
const SUPABASE_ANON_KEY = 'sb_publishable_...';
const supabaseClient = createClient(SUPABASE_URL, SUPABASE_ANON_KEY);

CRUD 패턴

CRUD는 Create(생성), Read(읽기), Update(수정), Delete(삭제)의 약자입니다.

Read (읽기) - GET 요청

async getOrders() {
  const response = await fetch(
    `${SUPABASE_URL}/rest/v1/orders?order=created_at.desc`,
    {
      headers: {
        'apikey': SUPABASE_ANON_KEY,
        'Authorization': `Bearer ${SUPABASE_ANON_KEY}`,
        'Content-Type': 'application/json'
      }
    }
  );
  return await response.json();
}

Create (생성) - POST 요청

async saveOrder(order) {
  const response = await fetch(
    `${SUPABASE_URL}/rest/v1/orders`,
    {
      method: 'POST',
      headers: {
        'apikey': SUPABASE_ANON_KEY,
        'Authorization': `Bearer ${SUPABASE_ANON_KEY}`,
        'Content-Type': 'application/json',
        'Prefer': 'return=representation'  // 생성된 데이터 반환
      },
      body: JSON.stringify(order)
    }
  );
  return await response.json();
}

Update (수정) - PATCH 요청

async updateOrder(id, order) {
  await fetch(
    `${SUPABASE_URL}/rest/v1/orders?id=eq.${id}`,
    {
      method: 'PATCH',
      headers: { /* apikey, Authorization, Content-Type */ },
      body: JSON.stringify(order)
    }
  );
}

Delete (삭제) - DELETE 요청

async deleteOrder(id) {
  await fetch(
    `${SUPABASE_URL}/rest/v1/orders?id=eq.${id}`,
    {
      method: 'DELETE',
      headers: {
        'apikey': SUPABASE_ANON_KEY,
        'Authorization': `Bearer ${SUPABASE_ANON_KEY}`,
      }
    }
  );
}

AI 주문 인식 시스템

가장 혁신적인 기능입니다. 카카오톡 메시지를 붙여넣으면 Gemini 2.5 Flash AI가 자동으로 제품명과 수량을 인식합니다.

동작 흐름

카카오톡 메시지
→
Gemini AI 분석
→
제품명+수량 추출
→
장바구니 추가

프롬프트 엔지니어링

AI에게 정확한 결과를 얻기 위해 상세한 지시문(프롬프트)을 작성합니다.

const prompt = `당신은 자동차 배기 부품 전문 주문서 분석 AI입니다.

제품 목록 (카테고리별):
${productList}

주문 텍스트:
${text}

핵심 규칙:
1. matchedProduct는 반드시 위 제품 목록의 정확한 이름
2. 각 줄에서 제품명과 수량을 추출
3. 오타, 줄임말, 띄어쓰기 오류를 자동 보정
4. "하나", "두개" 등 한글 숫자도 인식
5. 규격/숫자만 있으면 윗줄 카테고리를 이어받아 매칭
6. 슬래시(/)나 쉼표로 구분된 여러 제품도 분리
7. 매칭 불가 시 matchedProduct를 null로

응답 형식 (JSON 배열만):
[{"originalText":"원본",
  "matchedProduct":"정확한 제품명 또는 null",
  "quantity":숫자}]`;

Gemini API 호출

const response = await fetch(
  `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent?key=${apiKey}`,
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      contents: [{ parts: [{ text: prompt }] }],
      generationConfig: {
        temperature: 0.1,       // 낮은 온도 = 정확한 답변
        maxOutputTokens: 8192
      }
    })
  }
);
temperature 설정
temperature는 AI의 창의성을 조절합니다. 0에 가까우면 정확하고 예측 가능한 답변, 1에 가까우면 창의적이고 다양한 답변. 주문 인식에서는 정확성이 중요하므로 0.1로 설정합니다.

퍼지 매칭 (Fuzzy Matching)

AI가 인식하지 못한 제품명에 대해 레벤슈타인 거리 알고리즘으로 가장 비슷한 제품을 찾습니다. "스덴밴딩51"이라고 입력해도 "스텐밴딩파이프51"을 찾아줍니다.

const matchesSearchQuery = (productName, searchTerm) => {
  const np = normalizeText(productName);
  const ns = normalizeText(searchTerm);

  // 방법 1: 전체 포함 검사
  if (np.includes(ns)) return true;

  // 방법 2: 한글+숫자 그룹 분리 순차 매칭
  // "스덴밴딩51" -> ["스덴밴딩", "51"] -> 순서대로 매칭
  const parts = ns.match(/[가-힣a-z]+|\d+/gi);
  // ... 순차 매칭 로직 ...

  // 방법 3: 띄어쓰기로 분리된 단어 모두 포함 (순서 무관)
  const words = searchTerm.split(/[\s\-_]+/);
  return words.every(w => np.includes(normalizeText(w)));
};

    : item
));

    return null;
  }
}

const [settings, setSettings] = useState(() => {
  const saved = localStorage.getItem('notificationSettings');
  const defaults = { enabled: true, time: '09:00' };
  try {
    return saved ? JSON.parse(saved) : defaults;
  } catch (e) { return defaults; }
});

// 변경 시 localStorage에도 저장
const updateSettings = (newSettings) => {
  setSettings(newSettings);
  localStorage.setItem('notificationSettings',
    JSON.stringify(newSettings));
};

빌드와 배포

개발한 코드를 실제 사용자가 접속할 수 있도록 인터넷에 올리는 과정입니다. 이 프로젝트는 GitHub Pages를 사용하여 무료로 호스팅합니다.

빌드란?

비유: 원재료(JSX, Tailwind 클래스)를 완제품(순수 HTML, CSS, JS)으로 가공하는 과정입니다.

JSX + Tailwind
→
Vite Build
→
HTML + CSS + JS

배포 과정 (3단계)

1단계: 빌드

# dist/ 폴더에 배포용 파일 생성
npx vite build
절대 하면 안 되는 것!
npx vite build --base /pos-calculator/ 처럼 --base 플래그를 명령어에 넣지 마세요! Git Bash가 경로를 /Program Files/Git/pos-calculator/로 잘못 변환합니다. base 설정은 반드시 vite.config.js 안에서만 합니다.

2단계: 배포

# dist 폴더를 GitHub Pages에 배포
npx gh-pages -d dist

3단계: 확인

배포 후 1~2분 기다린 뒤 접속:

https://aijunny0604-alt.github.io/pos-calculator/

한 줄 배포 명령어

npx vite build && npx gh-pages -d dist

GitHub Pages 동작 원리

로컬 dist/
→
gh-pages 브랜치에 push
→
GitHub 웹서버 제공

base 설정이 중요한 이유

GitHub Pages는 https://username.github.io/repo-name/ 형태입니다. base를 설정하지 않으면 리소스 경로가 어긋나 빈 페이지가 됩니다.

base 없음 (오류)

요청: /assets/index.js
실제: /pos-calculator/assets/index.js
결과: 404 에러!

base 있음 (정상)

요청: /pos-calculator/assets/index.js
실제: /pos-calculator/assets/index.js
결과: 정상 로드!
